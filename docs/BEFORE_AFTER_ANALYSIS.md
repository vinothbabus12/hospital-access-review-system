# Before vs After Analysis: Quantitative Evaluation

## 1. Executive Summary

This document details the quantitative **Before vs After Analysis** for the Hospital Access Review System.
The evaluation compares:
1. **The Traditional Baseline Approach ("Before")**: A simulated spreadsheet-style periodic access review workflow where active staff accounts are routinely approved without usage logs, peer comparison, or risk scoring.
2. **The Evidence-Based Prototype ("After")**: An automated decision-support pipeline that correlates user entitlements against raw access logs, calculates peer-group baselines (role/application), computes multidimensional risk scores (0–100), and provides actionable recommendations (`APPROVE`, `REVIEW`, `REVOKE`, `MODIFY`).

The analysis synthesizes actual results generated by the quantitative baseline experiment (`experiments/results/baseline_results.json`) and the 10 expanded experiment scenarios (`experiments/results/expanded_results.json`).

> **Methodology Note:**
> *This comparison uses controlled synthetic hospital access-review data. The baseline represents a simulated spreadsheet-style review approach and does not represent historical hospital data.*

## 3. Mathematical Calculations & Formulas

### 3.1 Approval-Rate Reduction in Percentage Points
$$\text{Approval Rate Reduction (pp)} = \text{Baseline Approval Rate} - \text{Prototype Approval Rate}$$
$$\text{Approval Rate Reduction} = 83.5\% - 61.4\% = \mathbf{22.1\text{ pp}}$$

### 3.2 Relative Approval-Rate Reduction
$$\text{Relative Reduction (\%)} = \left( \frac{\text{Baseline Approval Rate} - \text{Prototype Approval Rate}}{\text{Baseline Approval Rate}} \right) \times 100$$
$$\text{Relative Reduction} = \left( \frac{83.5 - 61.4}{83.5} \right) \times 100 = \left( \frac{22.1}{83.5} \right) \times 100 = \mathbf{26.5\%}$$

The prototype achieves a **26.5% relative reduction** in approved access grants, directly curtailing over-permissioning.

## 4. Visualizations & Analytical Interpretation

### 4.1 Chart 1: Baseline vs Prototype Approval Rate
- **Baseline (Spreadsheet)**: `83.5%` approval rate. The traditional process rubber-stamps nearly all active accounts because reviewers lack contextual access logs and peer comparison data.
- **Prototype (Evidence-Based)**: `61.4%` approval rate. With audit logs and peer usage data visible, only validated, actively used privileges are approved.
- **Impact**: Eliminates **22.1 percentage points** of unwarranted approvals.

### 4.2 Chart 2: Prototype Decision Distribution
- **APPROVE (434 cases / 61.4%)**: Confirmed active privileges where staff usage matches role expectations.
- **REVOKE (203 cases / 28.7%)**: Unused privileges or inactive accounts that pose direct security risks.
- **MODIFY (70 cases / 9.9%)**: Over-privileged accounts where access scope or permissions should be reduced.

### 4.3 Chart 3: Entitlement Risk Distribution
- **LOW (434 cases / 61.4%)**: Minimal risk, routine clinical or administrative access.
- **MEDIUM (224 cases / 31.7%)**: Requiring secondary review or manager justification.
- **HIGH (49 cases / 6.9%)**: Immediate compliance alerts requiring revocation (e.g., inactive doctors retaining EMR access).

### 4.4 Chart 4: Expanded Experiment Scenario Comparison (E1 to E10)
Comparison of system behavior across simulated operational conditions:
- **E1 (Base Control)**: 273 affected cases, 49 high-risk cases.
- **E2 (Unused Privileges Added)**: Affected cases rise to 278 (+5 unused privileges identified).
- **E3 (High Privileges Injected)**: High-risk cases rise from 49 to 52 (+3 admin escalation detected).
- **E4 (Inactive Users)**: High-risk cases rise from 49 to 53 (+4 inactive staff detected).
- **E5 (Suppressed Usage)**: Affected cases rise to 278 as dormant access is flagged.
- **E6–E10 (Data Quality / Pipeline Stress)**:
  - E6 & E7: 203 and 178 duplicate events detected and purged.
  - E8: 271 delayed log arrivals detected.
  - E9: 5,171 out-of-order events re-sorted chronologically.
  - E10: 27 corrupt records safely isolated with zero pipeline failures.
